# Sweetch — Android edition

Нативная Android-адаптация оригинального Windows-проекта [krllmrzv/Sweetch](https://github.com/krllmrzv/Sweetch). Это не перенос Windows-бинарника: поведение и операции реализуются через Android API и доступные Android-движки.

## Уже реализовано в коде

- Круговое меню с секторами и альтернативная раскладка-пазл.
- Три категории по логике оригинала: **Конвертация**, **Инструменты**, **Действия**. Каталог фильтрует операции по типу выбранных файлов.
- Выбор нескольких файлов через Android Storage Access Framework и получение файлов/текста через системное меню «Поделиться».
- Изображения: конвертация JPEG/PNG/WEBP, сжатие и поворот с сохранением результата отдельно от оригинала.
- PDF: рендер страниц PDF в PNG и объединение нескольких изображений в PDF.
- Аудио: конвертация MP3/M4A/WAV, сжатие MP3 и нормализация громкости.
- Видео: конвертация MP4/WEBM, извлечение аудио в MP3, создание GIF, сжатие и извлечение миниатюры.
- Прямые HTTP(S)-файлы загружаются системным Android DownloadManager.
- Страницы медиасервисов передаются встроенному yt-dlp; готовые файлы копируются в `Downloads/Sweetch`.
- Импорт Netscape `cookies.txt` по явному выбору пользователя. Файл хранится в приватном no-backup каталоге приложения и не записывается в логи.
- Начальная интеграция Shizuku: проверка доступности и запрос разрешения.
- Companion-app PO Token Helper: проверка установки/объявленной Binder-службы, открытие приложения и переход к официальной странице релизов и настройкам Android.
- Необязательный системный жест: долго нажать на элемент, затем нажать уменьшение громкости. При включённой службе доступности Sweetch открывается с текстом/описанием элемента, если приложение-источник предоставляет эти данные.

## Важные ограничения

- Для системного жеста пользователь должен вручную включить Sweetch в настройках Android → Специальные возможности. Android не разрешает обычному приложению молча включать такую службу.
- Некоторые приложения не публикуют содержимое узлов для службы доступности, поэтому текст или URL могут быть недоступны. Жест не гарантирует извлечение содержимого из каждого приложения.
- yt-dlp поддерживает много сайтов, но результат зависит от текущих изменений на стороне сайта, форматов, региона и авторизации. Импорт cookies помогает только там, где их поддерживает экстрактор.
- **Получение PO Token через PotHelper ещё не подключено к загрузчику.** В Sweetch добавлены обнаружение установленного [Morphe PotHelper](https://github.com/MorpheApp/PotHelper), проверка его службы и переход к официальной установке. Сам PotHelper предоставляет GMS/Binder-совместимый сервис, а встроенный `yt-dlp-android` запускает yt-dlp внутри Python и пока не вызывает этот сервис. Поэтому наличие companion-app не означает, что Sweetch уже передаёт YouTube PO Token; для этого нужен отдельный адаптер протокола и проверка реального результата загрузки.
- Shizuku — необязательный мост, а не root. Запрос разрешения сам по себе ещё не подключает к приложению конкретные привилегированные операции; каждая такая операция требует отдельной реализации.
- Office-документы, архивы, субтитры, OCR и остальные операции полного каталога Windows Sweetch ещё предстоит переносить отдельными адаптерами. Их нельзя считать поддерживаемыми только потому, что они есть в Windows-версии.

## Сборка и проверка

Нужны JDK 17 и Android SDK API 35. Workflow `.github/workflows/android.yml` собирает debug APK и запускает unit-тесты на push в `main`, pull request и вручную:

    gradle --no-daemon :app:assembleDebug :app:testDebugUnitTest

Ожидаемый APK: `app/build/outputs/apk/debug/app-debug.apk`. GitHub Actions должен завершиться успешно, прежде чем сборку можно считать проверенной.
